# 28.10.2026 — Охота на 0xc000007b (Bad Image) на GOG 1.9

Инцидент-репорт: полный хронологический лог запусков, крашей, гипотез и виновников.
Урок: главный инструмент — байт-дифф + локальный тест загрузчика, а не запуски игры вслепую.

## Хронология

### 1. Установка (первый пресс мастера)
- Юзер запустил `INSTALL_v2.0.0_GOG19.bat` → ALL GREEN: 8/8 окон, хвост 4336 Б,
  SHA мастера `34e2abd2…`, бэкап `logic.dll.GOG19_stock.bak` создан.
- Установщик отработал идеально — но сам мастер был бракованным (см. ниже).

### 2. Запуск №1 → КРАШ
- `trm.exe` → диалог **«Bad Image» 0xc000007b** на `bin\logic.dll`.
- Игра откатана на сток `da62ed73…` (RESTORE), битый мастер сохранён для анализа
  (`bad19_master.dll`).

### 3. Гипотеза №1: мёртвый сертификат + устаревший CheckSum — ОПРОВЕРГНУТА
- Дифф сток→мастер (9 регионов) показал: все правки структурно валидны
  (COFF-шапка, SizeOfImage, запись .fgt5, 4 трамплина, хвост).
- Открытие: **сток 1.9 подписан Authenticode** (Security dir 0x8D0600/0x2D10),
  а сток 1.08 не подписан вообще — патч-движок, писанный по диффу 1.08, про
  сертификат не знал.
- Фикс-попытка: CheckSum→0 + Security→0 → кандидат `0ed72407…`.

### 4. Запуск №2 → тот же КРАШ
- 0xc000007b на logic.dll. Гипотеза с сертификатом не была причиной
  (но обнуление оставили — см. «Итоговый мастер»).

### 5. Прорыв: локальный тест загрузчика (LoadLibraryEx)
- Больше никаких запусков игры для проверки: `LoadLibraryEx(DONT_RESOLVE_DLL_REFERENCES)`
  в PowerShell воспроизводит решение загрузчика БЕЗ игры.
- STOCK 1.9 → OK; кандидат → **FAIL err=193** (ERROR_BAD_EXE_FORMAT = тот же 0xc000007b).
  Баг воспроизведён локально — можно бисектировать.

### 6. Бисекция
- Вариант «только шапка» (трамплины откатены, хвост обнулён) → **FAIL 193**.
- Вариант «только хвост» (мертвые байты, шапка стока) → OK.
- Виновник — в шапке.

### 7. ВИНОВНИК НАЙДЕН
Байт-дифф COFF-заголовка (0x128..0x138):

```
stock: 50 45 00 00 | 64 86 | 07 00 | 98 3f be 6a
bad:   50 45 00 00 | 64 00 | 08 00 | ...
```

Окно правки «NumberOfSections + timestamp» в генераторе собрано **со сдвигом на 1 байт**:
начиналось с 0x12D (старший байт machine) и писало туда `00`.
Machine стал `0x0064` — «DLL для несуществующего процессора» → 0xc000007b.
На 1.08 то же окно собралось правильно — поэтому там всё работало.
Хвост, трамплины, guard, SizeOfImage — не при чём.

### 8. Фикс и вердикт загрузчика
- Один байт: 0x12D `00`→`86` → мастер `65cff273…`.
- **LoadLibraryEx: OK** — загрузчик принял образ.

## Итоговый мастер v2 (канон)

`65cff273d6d2d808b12c9f836e9dbe019cadd5572938e2df63c31fb272898c3a` (9 257 984 B)

Отличия от битого `34e2abd2…`:
- machine 0x8664 восстановлен (главный фикс);
- CheckSum = 0 (паритет с проверенным 1.08-мастером);
- Authenticode Security dir = 0 (сертификат всё равно мёртв после модификации).

Судьба `34e2abd2…`: не «уже установлен», а **вход для ремонта** — установщик
чинит его 3 окнами (machine/CheckSum/Security) до `65cff273…`.

## Установщик v2 (INSTALL_LOGIC_v2.0.0_GOG19.ps1)

- Окно шапки исправлено: `off=300, old='64860700983fbe6a', new='64860800003fbe6a'`.
- Добавлены окна: `off=384` CheckSum→0, `off=464` Security→0 (итого 10 окон).
- Новая ветка BAD192: ремонт битого мастера 3 окнами.
- DRY191-ветка (ca639936) удалена — dry тоже был с битым байтом, никому не выдавался.
- Репетиция обеих веток (сток / ремонт) локально: результат побайтно = мастеру,
  SHA `65cff273…` — сходится.

## Уроки (→ DEV_PROCESS.md)
1. Ни один мастер не отдаётся юзеру без LoadLibraryEx-теста.
2. Полный байт-дифф сток→мастер обязателен к каждой сборке; лишний регион = брак.
3. Ошибка 193/0xc000007b диагностируется локально, игра не нужна.
4. Репетиция установщика — на обеих ветках входа.
