# 28.10.2026 — Зависание при выходе из игры (GOG 1.9, мастер 65cff273)

Новый баг после починки 0xc000007b (см. `2026-10-28_badimage_machine_byte.md`).
Игра работает в бою, но виснет при выходе. Локализация по регламенту.

## Контекст

### Запуск №3 — первый УСПЕШНЫЙ запуск на GOG 1.9
- Мастер `65cff273…` в `bin\logic.dll`, игра 1.09.1223 (build 94330).
- Загрузка: чистая (фикс machine-байта сработал).
- Бой (Схватка): все хуки отработали, лог `bin\FagotM2_debug.log` (3320 B):
  - множество срабатываний, все `VERIFY_IMMEDIATE=OK`, ни одного FAIL;
  - Перехват: `oldTeam=1 → newTeam=0` — корректно;
  - Шизофреник: `oldTeam=1 → newTeam=4` — корректно;
  - один кейс `oldTeam=0 → newTeam=4` (перехват своей цели? — уточнить у юзера);
  - `EMP_MATCH=YES` на каждом вызове диспетчера, `player_ally resolved=4`.
- Крашей в бою НЕТ.

### Проявление бага
- Выход из игры через меню → игра ЗАВИСЛА (окно не закрывается).
- Windows «Программа не отвечает» → юзер прибил процесс через «Закрыть программу».

## Бисекция

### Тест А: запуск → сразу выход, БЕЗ выстрелов → ЧИСТО
- Вывод: само присутствие патча и загрузка не ломают выход.
  Зависание требует, чтобы в сессии РАБОТАЛИ хуки (были выстрелы мода).

### Гипотеза (рабочая)
Use-after-free семейства Шизо/Перехват: при разрушении мира на выходе
наш хук/callback вызывается на уже освобождённых объектах (жертва, behavior,
vtable). REV1.9.2-guard закрывает гоночный кейс «жертва умерла до колбэка»
в бою, но путь teardown при выходе не покрыт.

### Дальше
- Тест B: один выстрел ЭМИ → выход. Чисто → ЭМИ невиновен.
- Тест C: один выстрел Шизо → выход.
- Тест D: один выстрел Перехват → выход.
- По виновнику — точечный guard на teardown-путь.
